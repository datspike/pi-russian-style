# Технический жаргон

Этот справочник применяется внутри обычной работы `humanizer-ru`, а не создаёт отдельный режим. Пользовательская просьба «только проверь, без правок» меняет только результат: нужен аудит без чистовика.

## Три категории

Перед правкой раздели английское слово или смешанный оборот на одну из трёх категорий:

| Категория | Действие | Примеры |
|---|---|---|
| Точный литерал | Оставить дословно | `session_before_compact`, `PI_RUNTIME_FINAL_CLI`, `npm run verify`, путь, имя API |
| Необходимый термин | Оставить или коротко пояснить при первом употреблении | runtime, sandbox, webhook, diff |
| Обычный рабочий жаргон | Перевести и назвать действие по-русски | follow-up → продолжение, retry → повторная попытка, runtime closure → набор зависимостей runtime, structured ledger → структурированный журнал |

Не переводи имена API, команды, пути, идентификаторы, названия библиотек, внешних продуктов, статусы и точные сообщения. Переводи слова вокруг них.

## Проверка необходимости

Для каждого английского слова вне кода ответь:

1. Это точное имя API, команды, поля или продукта?
2. Без этого термина читатель потеряет техническую точность?
3. Есть ли короткая русская формулировка, которая сохраняет действие и смысл?

Если ответ на первые два вопроса отрицательный, переведи слово. Если термин нужен, не добавляй разжёвывание для аудитории, которой оно не требуется.

## Для технических документов

README, инструкции, планы, отчёты и документы из `docs/` читай целиком. Проверяй не только отдельные слова, но и связность абзацев: читатель должен понять действие, исполнителя, результат, ограничение и следующий шаг без устных пояснений.
