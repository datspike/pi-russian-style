# pi-russian-style

Компактный пакет Pi для естественного русского технического языка.

Пакет добавляет короткое правило через `before_agent_start`, даёт отдельный интерактивный workflow Humanizer и поддерживает **явно включаемую** пассивную диагностику итоговых русскоязычных ответов на `message_end`. Диагностика не вызывает дополнительную модель, не редактирует готовые ответы и не меняет механизм сжатия контекста.

## Возможности

- русский технический стиль включён по умолчанию;
- команды `/russian-style status|on|off|toggle`;
- диагностика управляется отдельно через `/russian-style diagnostics status|on|off|toggle` и по умолчанию выключена;
- состояние хранится в `<каталог агента>/state/russian-style.json`;
- явная просьба отвечать по-английски действует только на текущий запрос;
- код, команды, пути, API, идентификаторы и дословные сообщения сохраняются;
- совместимость с `pohuy-mode`;
- интерактивная команда `/ru-clean` для редакторской правки предыдущего завершённого ответа;
- диагностические записи без исходного текста в `<каталог агента>/state/russian-style-diagnostics.jsonl`;
- короткое предупреждение только при сочетании сильных признаков.

## Установка

Клонируйте репозиторий и установите пакет из его корня:

```bash
git clone https://github.com/datspike/pi-russian-style.git
cd pi-russian-style
pi install "$PWD"
```

Проверка без постоянной установки:

```bash
pi --no-extensions -e "$PWD" --list-models
```

После установки перезагрузите текущую сессию Pi:

```text
/reload
/russian-style status
```

Не держите одновременно установленный пакет и копию расширения в `~/.pi/agent/extensions/russian-style/`: иначе Pi может загрузить два обработчика.

## Интерактивный Humanizer

`humanizer-ru` поставляется вместе с пакетом в `skills/humanizer-ru/`. Пассивная диагностика использует его lint вне критического пути TUI, но не меняет обычные ответы.

`/ru-clean` без аргументов выбирает последнее завершённое assistant-сообщение, создаёт неизменяемый source snapshot и draft. Модель применяет точные правки к draft, а `humanizer_patch_draft_set` по умолчанию сразу линтит новую revision. После успешного lint без `ERROR` и `humanizer_reader_check` для той же revision `humanizer_publish` публикует производное assistant-сообщение, не меняя источник.

`/ru-clean <запрос>` передаёт явную цель в `/skill:humanizer-ru`: например, `/ru-clean исправь этот файл` или `/ru-clean сделай чище docstring в Foo`. Суффиксный вариант тоже работает: `проверь этот док /ru-clean` преобразуется в тот же skill-запрос. Для того же сценария можно вызвать `/skill:humanizer-ru` напрямую.

`WARN` остаются контекстным сигналом; публикацию блокируют `ERROR`, недоступный lint или отсутствие `humanizer_reader_check` для текущей revision.

## Диагностика `message_end`

Обработчик `message_end` только проверяет тип сообщения и ставит работу в ограниченную очередь. Линтер и запись JSONL выполняются асинхронно. При переполнении новая задача пропускается; при завершении сессии активный процесс отменяется.

Запись содержит entry ID, модель, SHA-256 текста, длину, сведения о предшествующей инструментальной работе, версию правил, результат `humanizer-ru` и отдельные технические признаки. Сам текст повторно не сохраняется. Если сессионный JSONL недоступен, `entry_id` честно остаётся `null`.

Диагностика для нового профиля выключена. Старый state v1 мигрируется с сохранением прежнего включённого поведения; после этого флаг можно отключить отдельной командой.

Переменные окружения:

- `PI_CODING_AGENT_DIR` — каталог профиля Pi; default state и diagnostics следуют ему;
- `PI_RUSSIAN_STYLE_STATE_PATH` — явный путь state-файла, имеет приоритет над `PI_CODING_AGENT_DIR`;
- `PI_RUSSIAN_STYLE_DIAGNOSTICS_PATH` — явный путь диагностического JSONL;
- `PI_RUSSIAN_STYLE_LINTER_PATH` — путь `humanizer-ru/scripts/lint.py`;
- `PI_RUSSIAN_STYLE_LINTER_TIMEOUT_MS` — тайм-аут линтера, стандартно 1500 мс.

## Проверки

```bash
bun install --frozen-lockfile
bash run-checks.sh
```

`run-checks.sh` запускает TypeScript-тесты, строгую типизацию, тесты Python-линера и проверку текстовых инвариантов. Исследовательские корпуса, ручная разметка, benchmark-результаты и журналы в пакет не входят.
