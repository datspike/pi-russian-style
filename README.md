# pi-russian-style

Компактный пакет Pi для естественного русского технического языка.

Пакет добавляет короткое правило через `before_agent_start`, пассивно проверяет итоговые русскоязычные ответы на `message_end` и даёт отдельный интерактивный workflow Humanizer. Обычная диагностика не вызывает дополнительную модель, не редактирует готовые ответы и не меняет механизм сжатия контекста.

## Возможности

- русский технический стиль включён по умолчанию;
- команды `/russian-style status|on|off|toggle`;
- состояние хранится в `~/.pi/agent/state/russian-style.json`;
- явная просьба отвечать по-английски действует только на текущий запрос;
- код, команды, пути, API, идентификаторы и дословные сообщения сохраняются;
- совместимость с `pohuy-mode`;
- интерактивная команда `/ru-clean` для редакторской правки предыдущего завершённого ответа;
- фоновая диагностика итогового ответа с ограниченной очередью и тайм-аутом;
- диагностические записи без исходного текста в `~/.pi/agent/state/russian-style-diagnostics.jsonl`;
- короткое предупреждение только при сочетании сильных признаков.
- наблюдение за заполнением контекстного окна и локальное сравнение ранних и поздних ответов без модельных прогонов.

## Установка

Клонируйте репозиторий и установите пакет из его корня:

```bash
git clone https://github.com/datspike/pi-russian-style.git
cd pi-russian-style
pi install "$PWD"
```

Проверка без постоянной установки:

```bash
pi --no-extensions -e "$PWD"
```

После установки перезагрузите текущую сессию Pi:

```text
/reload
/russian-style status
```

Не держите одновременно установленный пакет и копию расширения в `~/.pi/agent/extensions/russian-style/`: иначе Pi может загрузить два обработчика.

## Интерактивный Humanizer

`humanizer-ru` поставляется вместе с пакетом в `skills/humanizer-ru/`. Пассивная диагностика использует его lint вне критического пути TUI, но не меняет обычные ответы.

`/ru-clean` выбирает последнее завершённое assistant-сообщение, создаёт неизменяемый source snapshot и draft. Модель применяет точные правки к draft, а `humanizer_patch_draft_set` по умолчанию сразу линтит новую revision. После успешного lint `humanizer_publish` публикует производное assistant-сообщение, не меняя источник.

Для файла, docstring или комментария используйте явный `/skill:humanizer-ru`: модель находит нужные фрагменты обычными инструментами, создаёт staging draft и затем применяет правку через обычный `edit`.

`WARN` остаются контекстным сигналом; публикацию блокируют только `ERROR` или недоступный lint. Подробный контракт: `docs/humanizer-integration-brief.md`.

## Диагностика `message_end`

Обработчик `message_end` только проверяет тип сообщения и ставит работу в ограниченную очередь. Линтер, дополнительные правила и запись JSONL выполняются асинхронно. При переполнении новая задача пропускается; при завершении сессии активный процесс отменяется.

Запись содержит entry ID, модель, SHA-256 текста, длину, сведения о предшествующей инструментальной работе, версию правил, результат `humanizer-ru` и отдельные технические признаки. Сам текст повторно не сохраняется. Если сессионный JSONL недоступен, `entry_id` честно остаётся `null`.

Новые записи используют схему `pi-russian-style-diagnostic/v2`: добавлены `stop_reason` и `context` с оценкой заполнения перед вызовом модели, хэшами инструкции и границами непрерывного наблюдения. Старые записи v1 читаются прежним интерфейсом, но не участвуют в сравнении окон. Пороги и `DIAGNOSTIC_RULES_VERSION` не изменены.

Переменные окружения:

- `PI_RUSSIAN_STYLE_DIAGNOSTICS_PATH` - путь диагностического JSONL;
- `PI_RUSSIAN_STYLE_LINTER_PATH` - путь `humanizer-ru/scripts/lint.py`;
- `PI_RUSSIAN_STYLE_LINTER_TIMEOUT_MS` - тайм-аут линтера, стандартно 1500 мс.

Измерение хранится в `benchmarks/results/2026-09-03-message-end.json`. Оно отдельно показывает синхронную стоимость постановки задачи, фоновое время реального `humanizer-ru`, состояние очереди под нагрузкой и изменение памяти до запуска фоновой работы. Бюджет критического пути и ограничение памяти проверяются в `run-checks.sh`.

## Ручная разметка

Локальная страница собирает стратифицированную выборку из `clean`, `record` и `notify`, восстанавливает текст по Pi entry ID и не копирует полные ответы в файл разметки.

```bash
python3 review/app.py
```

Открой `http://127.0.0.1:8765`. Общая оценка и полезность решения выбираются крупными переключателями или клавишами `1`-`7`. Плохие формулировки выделяются мышкой и сразу подсвечиваются жёлтым; щелчок по выделению удаляет его.

Разметка автоматически сохраняется в `.runtime/style-review/annotations.json`. В ней остаются оценки, SHA-256 и только выделенные фрагменты с позициями; исходные ответы читаются напрямую из сессионных JSONL.

Сводка сохраняется рядом с локальной разметкой:

```bash
python3 review/summarize_annotations.py \
  --annotations .runtime/style-review/annotations.json \
  --output .runtime/style-review/summary.json
```

Эти файлы содержат производные идентификаторы и выделенные фрагменты, поэтому остаются в `.runtime/` и не добавляются в Git.

## Наблюдение за длинными сессиями

После загрузки обновлённого расширения работай как обычно. Когда накопятся длинные участки, создай небольшую фиксированную выборку:

```bash
python3 review/app.py \
  --window-sample .runtime/window-review/sample.json \
  --output .runtime/window-review/annotations.json \
  --limit 20
```

Повторный запуск открывает тот же набор. Пара состоит из первого и последнего подходящего ответа одного участка: минимум четыре ответа, рост оценки заполнения минимум на 20 процентных пунктов. При наличии включается контрольная пара с `clean`. Если данных мало, команда сообщает об этом и не создаёт пустую выборку.

После ручной разметки:

```bash
python3 review/summarize_annotations.py \
  --window-sample .runtime/window-review/sample.json \
  --annotations .runtime/window-review/annotations.json \
  --output .runtime/window-review/summary.json
```

Этот режим не запускает модели, линтер или повторную оценку правил. Он сравнивает только полностью размеченные пары и отдельно показывает неполные. Модели и версии системной подсказки не смешиваются. Подробности и ограничения: `docs/window-observation.md`.



## Проверки

```bash
bun install --frozen-lockfile
bash run-checks.sh
```

В `eval/cases.json` хранится небольшой обезличенный регрессионный корпус. Полные исторические запуски и закрытая карта источников в пакет не входят.
